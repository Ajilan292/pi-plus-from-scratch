# Interfaces

This section defines the interfaces between different components of the system, including observation (state), action (command), and their representations. These interfaces are critical for ensuring consistency across simulation and real-world execution.

---

## Overview

The system communicates through well-defined interfaces. The two primary interfaces are:

- Observation interface (input to control policy)
- Action interface (output from control policy)

Consistency of these interfaces is essential for stable operation and sim-to-real transfer.

---

## Observation Interface

Observations represent the current state of the robot. They are used as input to control policies.

---

### Observation Components

Typical observation data includes:

- Joint positions
- Joint velocities
- Robot orientation
- Angular velocity
- Sensor readings (e.g., IMU)

The exact observation set may vary depending on configuration.

---

### Data Representation

Observations are typically represented as structured numerical data:

- Vectors or arrays
- Fixed ordering of elements
- Consistent dimensionality

Each element must have a clearly defined meaning.

---

### Units

All observation values must use consistent units:

- Position: radians
- Velocity: radians per second
- Orientation: quaternion or Euler angles
- Angular velocity: radians per second

Unit consistency is required across all components.

---

### Normalization

In some cases, observations may be normalized before being used by policies. Normalization may include:

- Scaling to a fixed range
- Centering values around zero

Normalization must be consistent between simulation and real systems.

---

## Action Interface

Actions represent commands generated by the control policy. They are sent to the robot for execution.

---

### Action Types

Common action types include:

- Target joint positions
- Target joint velocities
- Torque commands

The specific action type depends on the control mode.

---

### Data Representation

Actions are represented as:

- Fixed-size vectors
- One value per controllable joint

Each action element corresponds to a specific actuator.

---

### Units

Action values must use consistent units:

- Position commands: radians
- Velocity commands: radians per second
- Torque commands: Newton-meters

Incorrect units may result in unsafe behavior.

---

### Action Limits

All actions must respect system constraints:

- Joint position limits
- Velocity limits
- Torque limits

The system enforces these constraints to ensure safety.
